# WORMHOLE THREAD 5: EIP-7702 Delegation Exploit Landscape — Deep Dive
**Date:** 2026-10-18 (read-only research; no transactions, accounts, or contact made)
**Researcher:** Lodestone (subagent report)

EIP-7702 (`SET_CODE` for EOAs, live since Pectra, May 7 2025) lets any wallet delegate execution to smart-contract code via a type-4 transaction carrying a signed `authorizationList`. The exploit primitive: trick a user into signing one delegation authorization → attacker's contract gets persistent, account-level code execution as the victim's wallet. A delegation costs the victim nothing to sign, survives until explicitly cleared, and a *failed* transaction can still install the delegation (authorization is processed separately from the main call).

### Study-level numbers
- **USENIX Security '26 peer-reviewed study** (22.8B txs across 7 chains, 3,664,166 authorization txs through Jul 15, 2025): 63% tied to attacker contracts; 924 confirmed malicious contracts; **$2,362,848.76 confirmed losses**; separate **$10.14M in assets exposed** through 967 contracts still relying on broken `tx.origin`-style sender checks. Attackers rebind accounts to benign-looking code after thefts and pre-created **500 delegation targets with no code deployed yet**.
- **Wintermute (May–Jun 2025):** >97% of early mainnet delegations pointed to copy-pasted sweeper contracts ("CrimeEnjoyor").
- **Cloud9Japan (Sep 2026, raw mainnet sample, 40,528 authorizations):** 61.4% of authorizing EOAs were address-poisoning infrastructure run by just 15 sponsors; 3.1% delegated to auto-forward sweepers (compromised keys); 620 sweepers still armed, forwarding anything received.
- **2026 address-error study:** 17,270 cases of malicious delegation used against exposed accounts; Blockaid: $1.1B stolen H1 2026 (all causes).

### Estimate
Adding documented incident losses while avoiding double-counting the study's $2.36M (which overlaps the May–Jul 2025 incidents): **≈ $7.5–9M in publicly documented 7702-attributed thefts to date**, plus $10.14M still exposed in vulnerable contracts, plus an unmeasurable long tail of sweeper dust-drains (the "quietly eroding dust, airdrops and unmonitored wallets" slice). No single tracker publishes a running 7702-only total — the $2.69B YTD crypto-loss figure (early Oct 2026) is all-cause.

## 2. Who's tracking it

- **ScamSniffer** — first to flag the pattern (May 2025, $146K Inferno Drainer case); ongoing alerts on batch-transaction phishing; urges checking for phishing-account delegations.
- **SlowMist (Yu Xian)** — detailed technical analysis of the Inferno Drainer 7702 method; pre-launch risk guide (Mar 2025) covering phishing, replay, storage collisions; tracked WLFI delegation attacks (Sep 2025).
- **Wintermute** — the sweeper-contract research (97% finding); built "CrimeEnjoyor," a public warning-injection into verified malicious sweeper bytecode so Etherscan shows a "used by bad guys" notice.
- **Blockaid** — general phishing-loss tracking ($1.1B H1 2026); active exploit alerting (e.g., UNCX, Oct 14, 2026).
- **ExVul** — flagged the sven.eth $22.7K drain (Oct 14, 2026).
- **Academic/USENIX '26 researchers** — the 63% / 924-contract / $2.36M study; pushing wallets to whitelist audited delegation targets and display delegation clearly.
- **Ava Protocol** — after failing to rescue a swept wallet (Sep 2026), now scans wallets for 7702 code via Telegram/MCP and warns when funds were already swept.
- **ethereum.org** — published wallet guidance: whitelist audited implementations, show delegation targets, keep authorization history.

## 3. Defensive tooling — what exists and the real gap

**What exists:**
- **revoke.cash** — has a **Delegations tab** (added 2025) that *inspects* EIP-7702 delegations alongside Delegate.xyz/Warm.xyz delegations. ⚠️ Their own docs state: **"you cannot revoke them from there"** — most wallets don't let external dapps enable/revoke 7702 delegations, so you must revoke inside your wallet app. (One third-party roundup claims one-click revocation "now," but revoke.cash's own documentation contradicts this — unverified.)
- **eip7702.app** — standalone checker: paste an address, scans major chains, flags active delegation.
- **mywalletcheck.org** — "Wallet Delegation Check" tool with reporting templates (Etherscan labeling, Chainabuse); honest about limits (can't see approvals, can't recover).
- **Rabby Wallet** — approvals manager surfaces 7702 state.
- **MetaMask "Added Protection"** (Sep 2026, extension ≥13.45): forces preview-vs-onchain-outcome match; Red-Pill-attack defense; covers 13 EVM chains. Independent test (Oct 2026) of extension 13.47.0: external type-4 txs rejected ("not supported"), `wallet_signAuthorization` not exposed to dApps. The browser-extension attack surface is effectively closed on current MetaMask.
- **Manual:** `cast code <addr>` / `eth_getCode` — `0xef0100` + 20-byte delegate address; clear by sending a new type-0x04 authorization to `address(0)` (chainId `0` = all chains at once).

**The gap (build opportunity — precise):**
Nobody has built the actual **"revoke.cash for delegations."** What would be new vs. the above:
1. **Multi-chain delegation scanner** as a first-class product (not a tab inside an approvals tool) — check one address across all 7702 chains at once.
2. **Delegate reputation labeling** — malicious-delegate registry seeded from Wintermute's CrimeEnjoyor bytecode set + the 924 USENIX-verified contracts + poisoning/sweeper infrastructure (the Cloud9Japan 15-sponsor finding); green-list of audited account implementations (per ethereum.org guidance).
3. **One-click universal revocation UX** — type-0x04 to `address(0)` with chainId=0, abstracting wallet-by-wallet support differences (Rabby/MetaMask/safe flows). This is the piece revoke.cash explicitly does *not* do.
4. **Proactive monitoring/alerts** — notify when an address you watch gains a delegation (attackers install quietly; the Ava case sat 3 weeks before the sweep).
5. **Rescue workflow for the swept-wallet trap** — the Ava finding is critical: once hostile code is installed, even gas funding for the reset tx gets swept in the same block, and Rabby/MetaMask refused to sign their agent-prepared reset. A tool that solves *safe reset of an armed wallet* (sponsored reset, flash-rescue batching, or migrate-to-fresh-wallet automation) addresses a documented failure mode nobody handles.

Caution for the build: MetaMask already closed the dApp-signing vector in-extension, so the phishing surface is shifting to mobile/other wallets and to ambient triggers (any inbound transfer to a delegated wallet activates the code — no user action needed). The tool's value is detection + revocation + monitoring, not just signing-time warnings.

## 4. Attack mechanics

**Two distinct patterns:**
1. **Sweeper pattern (compromised key):** attacker holds the private key, signs a delegation to a copy-pasted sweeper contract (97% of early delegations). Anything arriving at the wallet is auto-forwarded. Cheap to run at scale — "cents each" for tens of thousands of addresses.
2. **Phishing-signature pattern (the genuinely new danger):** victim still holds their key. Attacker persuades them to sign a delegation, disguised as a "wallet upgrade," "security enhancement," or "AI assistant authorization." In the Inferno Drainer case, the victim signed what looked like a normal MetaMask flow; a hidden `execute` call ran a batch of fraudulent token transfers inside the delegated account — dozens of assets, one signature, no per-token popups.

**On-chain shape of a malicious delegation:** the victim EOA's code becomes `0xef0100 || <20-byte delegate address>` (23 bytes total). The attacker then submits an attacker-paid (sponsored) type-4 transaction carrying the victim's authorization — the victim pays nothing, which also means there's no gas-payment anomaly to notice. In the sven.eth case, the delegate contract contained a hardcoded controller address; the controller called `PodMining.claim()`, minted TAPEETH, and withdrew 9.1231 ETH in one transaction.

## 5. Trajectory

**Accelerating in sophistication, persistent in volume — not fading.**
- Share of malicious authorizations barely moved: 63% (through Jul 2025) → 61.4% poisoning infra (Sep 2026). Attackers didn't leave; the ecosystem normalized around them.
- Cadence of documented incidents is steady: Aug 2025 ($1.54M), Apr 2026 ($800K campaign), Aug 2026 ($292K), Sep 2026 (SPARK), Oct 2026 (sven.eth, $3.55M claim).
- **Sophistication markers:** post-theft rebind to benign-looking code (evades state-based monitors); 500 pre-created delegation targets with no code yet (dormant until CREATE2-style deployment); chainId=0 cross-chain authorizations; attacker-sponsored type-4 txs (victim pays nothing, sees nothing); ambient triggers (any inbound transfer activates the code — the Ava case shows a 3-week dormant-to-sweep gap); phishing framed as "AI assistant authorization" (2026 social-engineering update).
- **Defense is moving too:** MetaMask closed the extension vector (Sep 2026), ethereum.org issued wallet guidance, academic pressure for delegation whitelists. But detection/revocation UX and monitoring remain the unfilled hole — which is exactly where the next victims (sven.eth's still-active delegation) are sitting right now.
